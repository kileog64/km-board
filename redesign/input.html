📊 용량 관리 — 저장소 용량 확인, 오래된 데이터 압축, Storage 이전

📊 전체 업체 용량 모니터링

업체별 메인 문서(Firestore, 1MB 한도)와 상세데이터(키워드·시간대·일별, Firebase Storage) 용량이에요. 상세데이터는 Storage로 옮긴 뒤로는 문서당 1MB 같은 저장 실패 한도가 없어서, 이 표는 "위험 경보"가 아니라 Storage 무료 한도(팀 전체 월 5GB) 대비 참고용이에요.

🚚 상세데이터 Storage로 이전

예전에 저장된 업체는 키워드·검색어·시간대별·일별 상세데이터가 아직 Firestore(1MB 문서 한도)에 남아있을 수 있어요. 이 버튼은 그 업체의 데이터를 다시 불러왔다가 그대로 저장해서, 상세데이터를 자동으로 Firebase Storage로 옮겨요(내용은 바뀌지 않고 저장 위치만 바뀜). 이미 Storage에 있는 업체는 다시 눌러도 안전해요(변화 없음).

🧹 오래된 상세 데이터 압축

상세데이터는 이제 Storage에 저장돼서 용량 때문에 저장이 막힐 일은 거의 없지만, 오래된 달의 키워드/검색어/시간대별 상세 데이터가 더 이상 필요 없으면 여기서 지워 정리할 수 있어요. 최근 N개월은 그대로 두고, 그보다 오래된 달의 상세 데이터만 지워요. 매출·비용·전환수 같은 핵심 숫자와 일별 그래프는 그대로 유지돼요.
기본 24개월. 지운 키워드·검색어·시간대 데이터는 네이버가 약 1년치만 주기 때문에 다시 못 가져옵니다. 화면이 느려지거나 업체가 많이 늘었을 때만 쓰세요.

🔒 업체별 접근 권한 설정

특정 업체를 지정한 팀원 이메일만 볼 수 있게 제한해요. 비워두면(기본값) 로그인한 팀원 전체가 볼 수 있어요. 중요: 이 화면만으로는 실제로 막히지 않아요 — 아래에서 안내하는 Firestore 보안 규칙을 Firebase 콘솔에 붙여넣어야 실제로 적용돼요.

👑 관리자 계정 관리

여기 등록된 이메일로 로그인하면 전체 업체 데이터를 다 볼 수 있어요(관리자). 등록 안 된 계정은 자기 업체에 허용된 업체만 보여요(유저) — 위의 "업체별 접근 권한 설정"에서 업체마다 허용 이메일을 등록해줘야 해요.

🅱️ 브랜드검색광고 계약 등록

📋 검수표 내려받기

네이버 화면에 나오는 숫자와 우리 대시보드 숫자가 같은지 확인하는 엑셀을 만들어요.
· 월별 대조 — 달마다 노출수·클릭수·총비용·전환수를 나란히 놓고, 노란 칸에 네이버 숫자만 넣으면 차이가 자동으로 나와요
· 부가세 계산 — 네이버가 예전 기간은 부가세를 포함해서 주고 최근 기간은 빼고 줘요. 두 기준을 미리 계산해둬서, 네이버 숫자를 넣으면 그 날짜가 어느 쪽인지 알려줘요
· 일별 대조 — 고른 달의 하루하루를 펼쳐서 어느 날짜부터 어긋나는지 찾을 수 있어요
· 표본 대조 — 1일·3일·1주일·1개월 네 단계로 12구간을 자동으로 뽑아줘요. 어느 단계에서 틀리는지로 원인이 좁혀져요
· 연령·성별 — 연령 데이터(타겟팅 세그먼트 보고서)와 일별 데이터가 같은지 자동으로 대조하고, 연령대별·성별 표와 전환 유형별 내역을 같이 넣어요
플레이스는 수집 단계에서 이미 빠져 있어서 이 표에 안 나와요.

🤖 자동 수집 계정 연결

업체마다 네이버 검색광고 Key를 등록하면 자동 수집기가 매일 이 목록을 읽어 그 업체 데이터를 가져와요.
· 검색광고 Key 찾는 곳: 광고주센터에서 그 계정으로 전환 → 도구 > SA API 사용 관리 → 우측 상단 "검색광고 Key?" 패널의 숫자 (주소창의 계정 번호와 다를 수 있으니 꼭 이 패널 값을 쓰세요)
· 지칭은 이 계정을 뭐라고 부를지 적어두는 메모예요 (예: "sn라이프 메인", "마크힘 상표계정")
· API 라이선스·비밀키는 여기 저장하지 않아요 — GitHub Secrets에만 둡니다. 여기엔 공개 번호인 CUSTOMER_ID만 저장돼요.
📊 엑셀로 한번에 등록
① 양식 내려받기로 현재 업체 목록이 채워진 엑셀을 받아 → ② 검색광고 Key·지칭을 채우고 → ③ 그대로 올리면 전부 한번에 저장돼요.
새 업체도 빈 줄에 적으면 자동으로 생성됩니다 (업체명 + 검색광고 Key + 유형 B2C/DB). 성과 데이터는 자동 수집이 과거치까지 채워주니 따로 업로드 안 해도 돼요.
한 업체가 광고 계정을 여러 개 쓰면 같은 업체명으로 줄을 여러 개 만들고 계정마다 Key와 지칭을 적으세요 — 대시보드에선 한 업체로 합산되고, 캠페인 표에선 "지칭 · 캠페인명"으로 구분됩니다.
기존 업체는 업체명으로 매칭하니 이미 있는 업체명은 고치지 마세요 — 이름을 바꾸면 별개 업체로 새로 생깁니다.

🏷️ 광고계정 이름 붙이기

한 업체가 광고계정을 여러 개 쓰면 캠페인 앞에 계정번호가 붙어요(예: 2991469 · 중국_장가계). 번호만으로는 어느 계정인지 알기 어려우니 여기서 이름을 붙이면, 대시보드 왼쪽 광고계정 필터에 그 이름이 함께 표시됩니다.
계정이 하나뿐인 업체는 번호가 안 붙으므로 여기에도 나오지 않아요.
업체를 선택하면 계정 목록이 나옵니다.

📡 매체 이름 붙이기

네이버 보고서는 노출 지면을 숫자 코드로만 알려줘요(예: 8753). 여기서 이름을 붙이면 대시보드의 매체별 성과 표에 그 이름으로 표시됩니다.
비용이 큰 코드부터 나옵니다 — 보통 상위 1~2개가 네이버 통합검색(PC/모바일)이고, 나머지가 광고더보기·검색파트너예요. 광고관리시스템의 매체별 보고서와 비교하면 어느 코드가 무엇인지 알 수 있습니다.
업체를 선택하면 수집된 매체 코드가 나옵니다.

▶️ 지금 수집 실행

자동 수집(매일 새벽)을 기다리지 않고 지금 돌립니다. 버튼을 누르면 GitHub에서 수집이 시작되고, 끝나면 대시보드에 반영돼요(계정 수에 따라 몇 분~수십 분).
같은 날을 여러 번 수집해도 값이 중복되지 않아요 — 매번 그 달 전체를 다시 계산하는 구조입니다.
⚙️ 최초 1회 연결 설정
대시보드가 GitHub에 수집을 요청하려면 토큰이 필요해요. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token → Repository access는 수집기 저장소만, Permissions는 Actions: Read and write 하나만 켜고 생성하세요. (이 저장소의 수집 실행 외에는 아무것도 못 하는 토큰이에요)

· 날짜를 비우면 어제 하루만 · 기간을 넣으면 그 기간을 다시 받아 덮어씁니다(수치 정정용)
· 1년치 백필은 보고서를 수백 번 만들어서 몇 시간 걸릴 수 있어요. 중간에 끊겨도 다시 누르면 빠진 날부터 이어갑니다.

➕ 업체만 개별 추가

아직 광고 성과 데이터 없이 업체만 먼저 등록하고 싶을 때, 여기서 이름만으로 바로 추가할 수 있어요. 성과 데이터는 나중에 데이터 보고서를 업로드하면 자연스럽게 채워져요.

↩️ 최근 업로드 되돌리기

실수로 잘못된 파일을 올렸다면, 업체를 선택하고 바로 아래 버튼으로 되돌릴 수 있어요. (업체별로 가장 최근 저장 1회분만 보관돼요 — 그 이전 상태로는 되돌릴 수 없어요)

🗑️ 데이터 삭제

되돌릴 수 없어요. 삭제 전에 한 번 더 확인해주세요.
위 업체·기간을 그대로 두고, 키워드/검색어 데이터(TOP·제외추천)만 지워요. 매출·비용 등 나머지 값은 유지돼요.
